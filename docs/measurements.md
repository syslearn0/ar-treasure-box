## Phase 2a の検証結果（2026-08-28 / iPad, iOS Safari 26.6）

### (a) 画像ロスト後もアンカーがワールド座標に残るか ★最重要 → **合格**

計画 §9-#1 の唯一の関門。**通過した。**

- HUD 実測: `STATE: ANCHORED` / `画像: LOST (3.7s前)` / `ワールド追跡: NORMAL` の状態で
  アンカー座標 `0.301, -0.018, -0.919` を保持し続けた
- 目視でも、ターゲットを画面外へ出したあと立方体が実空間の同じ場所に残ることを確認
- 再アンカー 0 回、補正 111 回（すべて小さいズレの滑らかな補正の範囲内）
- 再認識ズレ 1.43cm / 5.10°

→ **「画像認識で位置を決め、以後は SLAM に任せる」構成は成立する。** 計画どおり進めてよい。

### (b) 座標系の向き → **仮定が正しかった**

- 青軸(Z)が紙面から垂直に立ち上がり、緑軸(Y)が紙面上を伸びる
- `src/scene/placeholder.ts` の `outward()` が返す `+Z` で正しい。**修正不要**

### (c) scale の単位系 → **原因判明。校正方法を確定**

- HUD 実測: `w=0.7500` が**常に一定**、`scale` は 0.6809 → 0.8944 → 1.0134 → 1.0366 と変動
- **`scaledWidth` は物理サイズではなく「高さを 1.0 に正規化したときの幅」** = 3:4 クロップの比 0.75 そのもの。
  image-target-cli が生成する JSON に物理サイズが一切入らないため、エンジンは実寸を知らない
- `scale` は SLAM の収束にともなう推定値。ターゲットのワールド幅 = `scaledWidth × scale`
- 採用した校正式: **`anchorRoot.scale = scale × scaledWidth / physicalWidthM`**
  - 当初 `scale` を掛け忘れており、立方体が約2.7倍大きく出ていた（実機で発覚し修正）
  - `scale` は毎フレーム反映すると脈打つので、**姿勢確定の瞬間の値で固定**し以後動かさない
- ⚠️ この式でも実寸とは一致しない。→ (e) を参照
- Phase 2a の印刷実寸: **L判 3.5×5インチ (89×127mm)**。3:4 画像を収めるので画像自体は 89 × 118.7mm

### (c-2) 閾値の単位バグ → **修正済み。認識しやすさが大幅に改善**

ワールド単位は実メートルの約2.7〜8.4倍。にもかかわらず閾値をメートルのつもりで書いていた。

| 設定 | 意図 | 実際の挙動 |
|---|---|---|
| `maxPositionSpreadM: 0.02` | 2cm のブレを許容 | **2.4mm** しか許容せず初期姿勢が確定しにくい（＝「認識がむずい」の主因） |
| `bigPosDeltaM: 0.1` | 10cm 動いたら再アンカー | **1.2cm** で再アンカー発動（実測25回） |

→ `worldToMeters()` を挟み、ワールド単位を実メートルへ戻してから閾値と比較するよう修正。
結果: 再アンカー 25 → 5、再認識ズレ 6.06cm(表示誤り) → **0.07cm / 0.23°**。

### (e) スケールの実寸一致 → **収束ゲート導入でほぼ解消（要目視確認）**

当初は枠が印刷物より 1.5〜2 倍大きかった。原因は式ではなく **SLAM のスケール推定が
収束する前に固定していたこと**だった。

経緯:
1. `scale` の掛け忘れ → 立方体が約2.7倍。式を `s = scale × scaledWidth / physicalWidthM` に修正
2. それでも合わない。`scale` が 0.327 〜 3.92（**約12倍**）振れることが判明
3. → **収束ゲート**を導入。ワールド追跡が `NORMAL` かつ、LOCKING 中に集めた
   `detail.scale` の 最大/最小 が `scaleStabilityRatio`(1.25) 以内でなければ確定しない。
   値も単発ではなく中央値を採用

実測（2026-08-28 11:23、Xserver本番URL）:
- `scale収束 1.01x (<=1.25)` — 収束してから確定できている
- `適用スケール 1.075`（`target scale 0.1262`）
- 立方体が画面上で印刷物幅の約35%を占める ≒ `3cm / 8.9cm = 34%` と整合

**⚠️ 「約35%」はスクリーンショットからの目測。枠と印刷物が実際に重なるかは
実機での目視確認が必要。Phase 4 着手前に確定させること。**

### (f) `[hidden]` が効かない CSS バグ → **修正済み**

`ANCHORED` なのにガイド枠と「もう少し近づけてください」が出たままだった。
ブラウザ標準の `[hidden] { display: none }` は UA スタイルシート由来なので、
作者スタイルの `display: flex` に負ける。`.guide` と `.controls` が該当していた。
→ `[hidden] { display: none !important; }` を追加。

### (d) trackingstatus の実際の値 → **実測値を確認**

- 観測されたのは `NORMAL / UNSPECIFIED` と `LIMITED / INITIALIZING`
- `RELOCALIZING` は今回未観測（来ない可能性がある。`onTrackingStatus` の分岐はそのまま残す）
- **SLAM 初期化中(`LIMITED / INITIALIZING`)はワールド座標そのものが動く**ため、
  そのまま姿勢確定・再アンカー判定をすると再アンカーが連発した（実測 10 回）。
  → `NORMAL` のときだけ再アンカーし、初期確定も `NORMAL` を最大3秒待つよう修正
