# 自分の 3D モデルを AR で動かすまで

プログラミングの経験がない人向けの手引きです。
黒い画面（ターミナル）にコマンドを打つ場面が出てきますが、
**打つのはこの文章に書いてあるものをコピペするだけ**で、意味は分からなくて構いません。

---

## 0. これは何をしているのか

```
カードの絵 ──① スマホのカメラで映す
                    │
                    ▼
             ② 「この絵だ」と気づく（画像認識）
                    │  ここで「絵が現実のどこに、どの角度であるか」を一度だけ決める
                    ▼
             ③ 以後はカメラの動きを追い続ける（SLAM）
                    │  スマホが自分の動きを推測するので、絵が画面から消えても
                    ▼  モデルは現実のその場所に残り続ける
             ④ その場所に 3D モデルを重ねて描く
```

**②は最初の一瞬だけ**、というのがこの仕組みの肝です。
だから横に回り込んでも、後ろから覗いても、そこに置いてあるように見えます。

あなたが差し替えるのは④の 3D モデルの部分です。①〜③はそのまま使えます。

**カードの絵は、紙に印刷しても、タブレットの画面に表示してもどちらでも構いません。**
この手引きは**タブレットに表示する方**を前提に書いています。
印刷より大きく映せるので認識が速く、刷り直しもいらないためです。

```
   iPad（絵を表示）            スマホ（AR を見る）
   ┌──────────┐
   │  ┌────┐  │                    ┌───┐
   │  │ 箱 │  │  ←── 映す ───      │ ▶ │
   │  └────┘  │                    └───┘
   └──────────┘
```

## 1. 用意するもの

| | |
|---|---|
| パソコン | Windows か Mac。どちらでもよい |
| Node.js | **LTS 版**を https://nodejs.org からダウンロードして入れる。全部「次へ」でよい |
| Blender | すでに使っているものでよい |
| 絵を映す端末 | iPad などのタブレット。無ければ紙に印刷でもよい |
| AR を見る端末 | iPhone なら **Safari**、Android なら **Chrome** |
| 定規 | 画面に当てて実寸を測ります。**必須です** |

> **なぜ AR 用にスマホが要るのか**: この AR エンジンはパソコンを非対応として弾きます。
> パソコンのブラウザで開くと「お使いの環境では動きません」と出ますが、**それが正常**です。
> 見た目の確認はパソコンでできますが、AR そのものは必ず実機で見ます。

## 2. まず、そのまま動かしてみる

自分のモデルに差し替えるのは後です。**先に「元の状態で動く」ことを確認**してください。
ここを飛ばすと、あとで動かなかったときに原因がモデルなのか環境なのか分からなくなります。

### 2-1. 準備（最初の一回だけ）

> まだダウンロードしていない場合は、先に
> [README の「手元に持ってくる」](../README.md#手元に持ってくる最初の一回だけ)
> を上から順に実行してください。`git clone` からのコマンドが1つずつ並んでいます。

このフォルダを開いた状態のターミナルで、

```bash
npm install
```

数分かかります。大量の文字が流れますが、最後にエラーが出ていなければ成功です。

### 2-2. カードの画像を作る

カードの画像はリポジトリに入っていません（QR コードに焼く URL が人それぞれなので）。
まず作ります。URL は今は何でもよいので、仮のものを入れてください。

```bash
node scripts/make-postcard.mjs "https://example.com/ar/"
```

2 つの画像ができます。

| ファイル | 用途 |
|---|---|
| `work/postcard.png` | カード全体（QR コード付き）。**紙に印刷する**用 |
| `work/postcard-target-region.png` | 追跡に使う領域だけを切り出したもの。**画面に表示する**用 |

### 2-3. iPad に表示する

`work/postcard-target-region.png` を iPad に送って（AirDrop でもメールでもクラウド経由でも
構いません）、**写真アプリで全画面表示**します。

この画像は縦 3:4 で、iPad の画面もほぼ同じ比率なので、画面いっぱいに出ます。
紙のハガキよりずっと大きく映せるぶん、**認識は速く、離れていても通ります。**

**表示するときの約束（4つ）**

1. **画面の明るさを 8 割以上に上げる。** 暗いと特徴が拾えません。
2. **自動ロックを切る。**
   設定 → 画面表示と明るさ → 自動ロック → **なし**。
   途中で画面が消えると当然、認識も切れます。
3. **画面の回転をロックする。** 途中で横向きになると別の絵として扱われます。
4. **一度表示したら、ピンチで拡大縮小しない。**
   表示倍率を変えると実寸が変わり、次の手順で入れた数字が合わなくなります。

### 2-4. 実寸を測って入れる ★ここを飛ばすと必ずズレます★

定規を iPad の画面に当てて、**枠のいちばん外側の横幅**を測ります。

```
 ├───────── ここを測る ─────────┤
 ┌──────────────────────────────┐
 │ ┌──────────────────────────┐ │
 │ │          箱の絵           │ │
 │ └──────────────────────────┘ │
 └──────────────────────────────┘
```

仮に **178mm** だったとします。これをメートルに直して（÷1000 するだけです）、
`src/config.ts` の上の方にある**この 1 行**を書き換えます。

```ts
const CARD_WIDTH_M = 0.178   // ← 測った幅（mm ÷ 1000）
```

**直すのはここだけです。** 3D の箱の大きさもキャラクターの位置も、この値から自動で計算されます。

> **なぜ必要か**: このアプリは「絵の実寸」を基準にして、現実の大きさを決めています。
> 実寸の指定が 2 倍ずれていれば、机の上に出てくるキャラクターも 2 倍の大きさで出ます。
> 印刷物なら 88mm 固定ですが、画面表示は端末と表示倍率で変わるので、測るしかありません。

### 2-5. 起動する

```bash
npm run dev:https
```

こんな行が出ます。

```
  ➜  Network: https://192.168.1.23:5173/
```

この `Network:` の方の URL を、**AR を見るスマホのブラウザに手で打ち込みます**
（iPad ではなくスマホの方です）。

### 2-6. スマホ側

1. 「この接続ではプライバシーが保護されません」のような警告が出ます。
   「詳細」→「このサイトにアクセスする（安全ではありません）」で進んでください。
   自分のパソコンなので問題ありません。
2. 「カメラを起動する」を押す → カメラの許可を求められるので許可
3. 絵を表示した iPad を机に置く（真上に向けると天井の照明が映り込むので、少し傾けるとよい）
4. **絵が画面いっぱいになるまでスマホを近づける**
5. 箱が立体になってキャラクターが出てくれば成功

出たあとは、スマホを動かして横や後ろから見てみてください。
**iPad を画面の外に出しても、モデルはその場に残ります。** それが正常な動作です。

### 2-7. ここでつまずいたら

**環境まわり**

| 症状 | 原因 | どうする |
|---|---|---|
| パソコンで開いたら「動きません」と出る | 仕様です | スマホで開く |
| `Network:` の行が出ない／`localhost` しか出ない | パソコンがネットワークに繋がっていない | Wi-Fi に繋ぐ |
| スマホでその URL を開いても真っ白／繋がらない | パソコンとスマホが**別の Wi-Fi** にいる | 同じ Wi-Fi に揃える。ゲスト用 Wi-Fi は端末同士を遮断するので不可 |
| 同上（Windows） | ファイアウォールが弾いている | 起動時に出る「アクセスを許可しますか」で**プライベートネットワーク**にチェックして許可 |
| カメラの許可ダイアログが出ない | 許可はボタンを押した直後にしか要求できない仕組み。一度断ると出なくなる | ページを再読み込みして、もう一度ボタンを押す。それでも駄目ならブラウザ設定でこのサイトのカメラ許可をリセット |

**画面に表示しているがゆえの問題**

| 症状 | 原因 | どうする |
|---|---|---|
| 途中で画面が暗くなって認識が切れる | 自動ロック／明るさの自動調整 | 自動ロックを「なし」に。明るさの自動調整もオフに |
| テカって認識しない | 蛍光灯や窓の映り込み。**画面は紙よりずっと反射します** | iPad を傾ける、照明の真下から外す、明るさを少し下げる |
| 細かい縞模様（モアレ）が見える | 画面の画素とカメラの相性 | スマホを少し近づける／離すと消える。認識自体には支障が出にくい |
| いつまでも認識しない | 遠い／画面が暗い／傾けすぎ | 絵が画面いっぱいになるまで近づける。真正面から少し外した角度が映り込みに強い |
| 認識したが箱の大きさが絵と合わない | `CARD_WIDTH_M` が実測と違う | 定規で測り直す。表示をピンチで拡大していないか確認 |
| 出たモデルが変な場所に取り残される | 認識したあとに **iPad を動かした** | モデルは「現実のその場所」に残る仕様。**一度認識したら iPad は動かさない** |
| だんだんモデルの位置がずれていく | まわりに模様がなく、スマホが自分の動きを見失っている | 机の上にマグカップや本など、模様のあるものを置く。真っ白な机だけの環境がいちばん苦手 |

## 3. 自分のモデルに差し替える

### 3-1. Blender 側で守ること

ここを守らないと、ほぼ必ずズレます。**5つだけです。**

**① 実寸で作る。単位はメートル。**

Blender の 1 マスは 1 メートルです。何も考えずに人を作ると、AR では**身長 1.7m の巨人**が
机の上に出ます。机の上に乗る大きさ（8cm なら `0.08`）で作ってください。

Blender の右側 → シーンプロパティ → 単位 → 単位系「メートル法」、長さ「センチメートル」に
しておくと数字が読みやすくなります。

**② 原点（0,0,0）が、絵の中心に来る。**

モデルの**足元**を原点（Z=0）に合わせてください。
足元が Z=0 より上だと宙に浮き、下だと机に埋まります。

**③ 上は +Z。** Blender の標準のままでよい。書き出すときに自動で変換されます。

**④ 正面は −Y 方向。** 絵を手前から見たときに顔が見える向きです。
逆を向いていたら、Blender で 180° 回すのがいちばん確実です
（コード側で直すこともできます。3-4 の `spinRad` を参照）。

**⑤ 書き出す前に、拡大縮小と回転を「適用」する。**

全部選んで（`A`）→ `Ctrl + A` → **「全トランスフォーム」**。
これをしないと、スケールが 0.01 倍などのまま書き出され、Web 側で予想外の大きさになります。

> **大きさの目安**: 三角形 5 万個以下、テクスチャは 1 枚 2048px 以下、
> ファイル全体で 8MB 以下。スマホは非力なので、これを大きく超えると
> 読み込みに時間がかかったり、途中で落ちたりします。
> （このリポジトリに入っている既定のモデルは 190KB です）

### 3-2. 書き出す

Blender で **ファイル → エクスポート → glTF 2.0 (.glb)**

右側のパネルで確認する項目（Blender の版によって場所や表記が少し違います）:

| 項目 | 設定 | なぜ |
|---|---|---|
| フォーマット | **glTF Binary (.glb)** | 1 ファイルにまとまる。`.gltf` だと分割されて扱いづらい |
| インクルード → 選択物のみ | **オフ** | 全部書き出す |
| トランスフォーム → **+Y Up** | **オン** | Web の 3D は「上が Y」。ここが違うとモデルが倒れる |
| データ → メッシュ → モディファイアーを適用 | **オン** | サブディビジョン等が反映される |
| データ → シェイプキー | **オン** | 表情や変形を使うなら必須 |
| データ → スキニング | **オン** | ボーンで動かすなら必須 |
| アニメーション → アニメーション | **オン** | |
| アニメーション → モード | **シーン** | タイムライン全体を書き出す |

保存先は **`public/assets/`** フォルダの中。ファイル名は好きなもので構いません（例: `mymodel.glb`）。

### 3-3. まず AR なしで確認する

いきなり AR で試すと、モデルが悪いのか AR が悪いのか切り分けられません。
**GLB だけを見るページ**が用意してあります。

`src/glbtest.ts` の上の方にある行を、自分のファイル名に変えます。

```ts
const GLB_URL = './assets/mymodel.glb'
```

そして、

```bash
npm run dev
```

パソコンのブラウザで **http://localhost:5173/glb-test.html** を開きます。
マウスでぐるぐる回せます。ここで正しく出て動けば、モデル側は問題ありません。

### 3-4. AR で使うように指定する

`src/config.ts` のいちばん下の `AVATAR` を書き換えます。

```ts
export const AVATAR = {
  url: './assets/mymodel.glb',   // ← 自分のファイル名に

  // 絵の中心から見て、モデルをどれだけずらすか（メートル）
  // x: 右が＋ / y: 上が＋ / z: 絵から手前に浮かせる方向が＋
  offset: {x: 0, y: 0, z: 0},

  // 大きさの倍率
  scale: 1,

  // 絵に対する向き。後ろを向いていたら Math.PI にする
  spinRad: 0,
}
```

> **いちばん簡単なやり方**は、`offset` を全部 `0`・`scale` を `1` にしておいて、
> **位置と大きさは Blender 側で合わせてしまう**ことです。
> 慣れた道具で調整できるうえ、数字の意味を考えずに済みます。
>
> 既定のモデルでは、絵に描かれた箱とモデルの箱を重ねる必要があったので
> ここに計算式が入っていますが、自分のモデルなら不要です。

スマホで見ながら数字を少しずつ変えて合わせます。`npm run dev:https` を動かしたまま
ファイルを保存すると、スマホの画面が自動で更新されます。

### 3-5. アニメーション

このアプリは、**1 本のタイムラインの前半を「登場」・後半を「待機」として切り分けて**使います。
登場は 1 回だけ再生、待機はずっとループします。

Blender 側では、1 本のタイムラインに続けて並べてください。

```
フレーム    1 ────────── 195 │ 196 ────────── 315
            登場（1回だけ）  │  待機（ループ）
```

そして `src/scene/avatar.ts` の上の方にある**この 3 行**を、自分の数字に直します。

```ts
const FPS = 30
const INTRO = {start: 1, end: 195}
const IDLE  = {start: 196, end: 315}
```

**注意点:**

- **30fps 前提**です。Blender 側のフレームレートも 30 に揃えてください
  （出力プロパティ → フレームレート）。ここが 24 だと再生速度がずれます。
- **ループの継ぎ目**: 待機の最後のフレーム（315）と最初のフレーム（196）を
  **同じポーズ**にしてください。違うとループのたびにカクッとなります。
- glTF に書き出すと、**アニメーションはオブジェクトごとにバラバラのクリップになります**
  （1 本にまとまりません。実測で確認済み）。このアプリは全部を同時に再生するので、
  あなたが気にする必要はありません。

### 3-6. 名前で特別扱いしているもの

以下の名前のオブジェクトがあると、Web 側が勝手に手を加えます。

| Blender でのオブジェクト名 | 何が起きるか |
|---|---|
| `Chr_Paper` | `src/config.ts` の `MESSAGE` で書いた文字が、テクスチャとして自動で貼られる |
| `Box_Interior_Occluder` | 真っ黒な不透明マテリアルに差し替えられる（箱の中を暗くして下半身を隠すため） |

**使わないなら、その名前のオブジェクトを作らなければよいだけ**です。
別の名前にしたい場合は `src/scene/avatar.ts` の中の同じ文字列を書き換えてください。

手紙の文字は GLB に焼き込んでいません。Web 側で毎回描いて貼っているので、
**文面を変えるのに Blender を開く必要はありません。** `src/config.ts` の

```ts
export const MESSAGE = {
  label: 'MESSAGE',      // 小さく出る一言
  heading: 'ありがとう',  // 大きく出る一行
  lines: [],             // 続く行
}
```

だけで変わります。

## 4. Blender で実際に踏んだ落とし穴

このプロジェクトを作る過程で実際に引っかかったものです。

| 現象 | 原因 |
|---|---|
| Web で見たらモデルが横倒し | 書き出し時の **+Y Up** が入っていない |
| Web で見たら極端に大きい／小さい | 拡大縮小を適用（`Ctrl+A`）していない、または実寸で作っていない |
| 「縦方向のアニメが動いていない」と思った | glTF では **Blender の Z（縦）が Web の Y** になる。見る軸を間違えていた |
| ボーンに付けたパーツが全部原点に潰れた | ボーンへのペアレント直後に `matrix_world` を代入しても効かない。**すでにボーンに付いているメッシュの子**にするのが確実 |
| 手に持たせたものが変な所へ飛ぶ | 手のボーンにペアレントすると、手の回転が大きなオフセットを振り回す。ルートの子にして軌跡を直接付ける方が制御しやすい |
| 潰れ／伸びが逆になる | ボーンの**ローカル Y** が骨の長さ方向。X や Z ではない |
| 隠したパーツが箱の底を突き抜けた | 移動で隠すと他のものを貫通する。**スケールを 0 近くにして隠す**方が安全 |
| スクリプトからマテリアルを設定したのに灰色のまま | Blender の UI が日本語だと、ノード名やソケット名まで日本語（「プリンシプルBSDF」）になる。名前ではなく種類で探す必要がある |

## 5. 完成したら人に見せる

```bash
npm run build
```

`dist/` フォルダができます。この**中身**を、レンタルサーバーなどの公開フォルダに置きます。

- サーバー側に必要なものは何もありません（Node.js もデータベースも不要）
- **HTTPS でないとカメラが動きません。** `https://` で開けることを必ず確認してください
- `.htaccess` という**隠しファイル**を上げ忘れがちです。FTP ソフトの「隠しファイルを表示」を有効に

見せ方は 2 通りあります。

**画面に表示して見せる場合** — 相手には URL を送るだけで済みます。
`work/postcard-target-region.png` を自分の iPad に出しておいて、
相手のスマホでその URL を開いてもらいます。QR コードは要りません。

**紙で渡す場合** — 公開した URL で QR を焼き直してから印刷します。

```bash
node scripts/make-postcard.mjs "https://自分のURL/"
```

`work/postcard.png` を **実寸 100%** で印刷してください
（印刷設定の「用紙に合わせる」を必ずオフに。大きさが変わると 3D と絵がずれます）。
このとき `src/config.ts` の `CARD_WIDTH_M` は **0.088** に戻します。

> ⚠️ **QR を焼いたあとに URL を変えると、配った紙が全部使えなくなります。**
> 印刷は URL が確定してから。

詳しい配置手順は [deploy-xserver.md](deploy-xserver.md) にあります。
